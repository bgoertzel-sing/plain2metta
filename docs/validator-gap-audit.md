## Appendix N/P categories not yet covered

The design summary for Appendices N/P recommends validation beyond v0.1's structural profile. These categories are not yet implemented:

- Information-flow checks: a first conservative slice now covers input/output declaration, dependency-direction, temporal-availability, and circular-dependency termination. Component-level data-path edge extraction now detects explicit "X reads from Y" / "X writes to Y" / "X consumes from Y" / "X depends on Y" patterns and creates `DataFlowEdge` atoms with an `information-flow-data-path-declared` obligation. Transitive dependency chain detection builds an adjacency graph and emits `information-flow-transitive-dependency-reviewed` obligations. Graph-based cycle detection via DFS coloring emits `information-flow-cycle-detected` obligations when actual cycles exist in the extracted edge graph. Fan-out/fan-in concentration detection flags components with >=3 edges in one direction. Bottleneck node detection flags components that are both high fan-in AND high fan-out (>=3 in each dimension), emitting `information-flow-bottleneck-node-reviewed` obligations. Source/sink identification and BFS-based reachability analysis check graph completeness. Isolated component detection flags components mentioned with broader data-flow verbs but not connected to any edge. Redundant path detection flags when multiple distinct paths (direct + indirect) connect the same pair of nodes. Temporal ordering impossibility detection extracts explicit "A before/after/then/precedes/follows B" statements and detects impossible cycles. Cross-layer consistency checks flag contradictions between DataFlowEdge direction and TemporalOrderEdge declarations. Dependency depth / critical path length detection flags deep dependency chains (>=4 edges). Deeper data-path inference, multi-clause source inheritance, and stronger temporal impossibility checks are not yet covered.
- Time and temporal-availability checks beyond the first ML feature-availability slice, including freshness, availability windows, and temporally impossible claims.
- Broader methodology validation beyond the first ML/time-series slices, including experiment design, leakage patterns beyond explicit preprocessing-order, future/label-as-feature, feature availability, and random/shuffled split wording, metric appropriateness beyond the current conservative classification-vs-forecast keyword review, and richer baseline/uncertainty semantics beyond generic-vs-named comparator/method evidence.
- Process/resource discipline, including runtime resources, scheduling, deployment/process constraints, and backend artifact lifecycle.
- Broader security/privacy semantics beyond the first keyword-level slice, including richer threat models, data-classification facets, policy provenance, and executable access-control proofs.
- Phase 2 semantic objects (`Scope`, `EpistemicStatus`, `Evidence`, `Interpretation`, `Bridge`) and associated validation.
- Phase 3 facets for witnesses/backend artifacts, process/resource placeholders, and revisions.
- SUMO/EXPO/Hyperseed bridge-table validation.
- PLN confidence propagation or contradiction handling.
- Rholang and MeTTa-IL target-profile validation.

## Highest-priority v0.2 gaps

1. **Deepen methodology validation for the ML/time-series fixture.** The first v0.2 slices now cover metric declaration, a conservative metric/task appropriateness review, horizon/frequency, reproducibility evidence, train-only preprocessing fit scope, explicit preprocessing-order review, future/label-as-feature leakage review, prediction-time feature availability review, real-time/current feature freshness review, temporal split-order review, baseline comparison, named comparator review, uncertainty/error bars, and named uncertainty-method review. Next extend toward richer comparator/uncertainty semantics and stronger metric appropriateness once target/task facets are explicit.
2. **Information-flow and temporal availability checks.** A first conservative information-flow validation slice now covers input/output declaration, dependency-direction declaration, temporal-availability review, circular-dependency termination review, component-level data-path edge extraction with `DataFlowEdge` atoms, transitive dependency chains, graph-based cycle detection, fan-out/fan-in concentration, bottleneck node detection, source/sink identification, reachability analysis, isolated component detection, and redundant path detection. Temporal ordering impossibility detection, cross-layer consistency, and dependency depth / critical path length detection are also covered. Missing evidence becomes `MissingInformationFlowEvidence` blocking questions. Next extend toward multi-clause source inheritance, richer data-path inference, and stronger temporal impossibility checks once Phase 2/3 objects exist.
3. **Deepen security/privacy semantics.** The first keyword-level slice now covers secrets, secret log-exposure, credential rotation/expiry/revocation, PII/privacy controls, data-classification declaration, encryption-scope/key-management review, lawful-basis/consent review, retention/deletion review, purpose-limitation review, data-subject rights review, rights-request authentication review, PII access audit/logging review, incident-response/breach-notification review, data-residency/cross-border transfer review, third-party/vendor sharing review, access boundaries, privilege-escalation review, authentication/session-management review, authentication/API abuse-protection review, API authorization/scope review, authentication/API transport-protection review, API/webhook input-validation review, webhook/callback request-authenticity review, and destructive-action safety as Unknown/question scaffolding. Next steps are richer data-classification facets, policy provenance, and stronger access-control checks once Phase 2/3 objects exist.

Process/resource discipline should follow once Phase 3 placeholders or backend artifact records exist; until then, it has less schema surface to validate.
